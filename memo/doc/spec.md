# 仕様

この文書は、今のところディスクイメージ・音源・ステータス行の部分だけを書いている。

## ディスクイメージ

`FD0`～`FD3`（CONFIGファイル、または `-D` スイッチ）に指定できるファイルは次の2種類。形式はドライブごとに、ファイルを開くたびに中身から判定する。

- 2D形式：320KBのベタイメージ（1セクタ256バイト、1トラック16セクタ、両面80トラック）。従来どおり
- D88形式：D88形式のイメージ。形式の定義は https://github.com/gorry/d88toolg の `spec_d88.md`

### ディスクイメージの入れ替え

CONFIGファイルには、ドライブごとに10個までのディスクイメージを書ける。

| 指定 | ドライブ | 内容 |
|---|---|---|
| `FD0`～`FD3` | 0～3 | 起動時に入っているイメージ |
| `FD10`～`FD13` | 0～3 | 入れ替え用のイメージ（1番め） |
| … | | |
| `FD90`～`FD93` | 0～3 | 入れ替え用のイメージ（9番め） |

- `FDxy` の `x`（1～9）が入れ替えの順番、`y`（0～3）がドライブ
- `-D` スイッチで指定できるのは `FD0`～`FD3` だけ。`-D` で指定したドライブは、CONFIG の `FD0`～`FD3` より優先する（従来どおり）
- エミュレータの実行中に OPT.2 を押しながらテンキーの 0～3 を押すと、その番号のドライブのイメージが次のものに替わる
  - ドライブ0なら `FD0` → `FD10` → `FD20` → … → `FD90` → `FD0` の順
  - 指定のない番号は飛ばす。ほかに指定がなければ何も起きない
  - キーを押したままにしても、進むのは1つだけ（キーリピートでは進まない）
  - 押し直せば、押した回数だけ進む。X1 がディスクを使うのを待たなくてよい
- 実際にファイルが替わるのは、キーを押したあと X1 のプログラムが最初にＦＤＣへコマンドを書いたとき。それまでに押した回数をまとめて進める。一周して元のイメージに戻ったときは、ファイルを開き直さない
- 入れ替えのとき、開いていたファイルは閉じる。そのドライブを使っている最中（モーターON）なら、新しいイメージをすぐ開く。形式（2D・D88）は開き直すたびに判定する
- ヘッドの位置（トラック）は入れ替えても変わらない
- 入っているイメージの名前はステータス行に出る（「ステータス行」を参照）

### 起動時の確認

CONFIG と `-D` スイッチを読んだあと、`FD0`～`FD3`・`FD10`～`FD93` に指定されたファイルを一度ずつ読み込みモードで開いて、すぐ閉じる。

- 開けないファイルがあれば、1つにつき1行 `FD10=ファイル名 が開けません` と表示する
- 1つでもあれば、最後に `何かキーを押すと続行します` と表示してキー入力を待ち、そのまま起動する
- 開けなかったドライブは、従来どおりディスクが入っていないものとして動く
- 中身（形式や大きさ）は調べない

### D88形式の判定

次をすべて満たすファイルをD88形式として扱う。満たさなければ2D形式として扱う。

- 先頭から688バイト（`$2B0`）が読める
- ライトプロテクト（`$1A`）が `$00` か `$10`
- ディスクの種類（`$1B`）が `$00`・`$10`・`$20`・`$30`・`$40` のどれか
- ディスクサイズ（`$1C`）が688以上で、ファイルの大きさ以下
- トラックオフセットテーブルの先頭160個のうち、0でない最小の値が `$2A0` 以上
- テーブルの0でない値がすべてディスクサイズより小さい

テーブルの個数は、最初のトラックの位置が `$2B0` より前なら160個、そうでなければ164個とする。

### D88形式でできること

- 1トラックのセクタ数、セクタの大きさ（128・256・512・1024バイト）、セクタの並び順は、イメージに書かれているとおりに扱う
- ヘッダのライトプロテクトが `$10` なら書き込み禁止になる。ファイルの属性が読み込み専用のときも、従来どおり書き込み禁止になる
- トラックNo.は `シリンダ*2+サイド` でテーブルを引く。ディスクの種類による読み替えはしない

### ＦＤＣのコマンドごとの動作（D88形式）

| コマンド | 動作 |
|---|---|
| リードデータ | C がトラックレジスタ、R がセクタレジスタと同じセクタを読む。転送するバイト数はセクタのデータの大きさ |
| リードデータ（m） | セクタレジスタの値から R を1ずつ増やし、見つかる間のセクタを続けて読む。終了時は Record Not Found |
| リードアドレス | トラックにあるセクタの ID（C・H・R・N）を、呼ばれるたびに順に返す。CRC は 0 |
| リードトラック | トラックのセクタのデータを並び順につなげて返す。`$1900` バイトに足りない分は 0。ギャップや ID は返さない。終了時は Lost Data |
| ライトデータ | セクタのデータを書き換える。削除フラグとステータスは 0 にする |
| ライトデータ（m） | リードデータ（m）と同じ範囲のセクタに続けて書く。終了時は Record Not Found |
| ライトトラック | トラックにあるすべてのセクタのデータを `$FF` で埋め、削除フラグとステータスを 0 にする。セクタの構成は変えない |

ステータスは次のように返す。

| 状況 | ステータス |
|---|---|
| トラックがない（オフセットが0）、セクタが見つからない | Record Not Found（`$10`） |
| セクタのステータスが `$A0`（IDのCRCエラー）・`$E0`（IDなし） | そのセクタはないものとして扱う |
| セクタのステータスが `$F0`（データなし）、データの大きさが0 | Record Not Found（`$10`） |
| セクタのステータスが `$B0`（データのCRCエラー） | 読み終わったときに CRC Error（`$08`） |
| 削除フラグが `$10`、またはステータスが `$10` | 読み終わったときに Record Type（`$20`） |
| トラックがないところへのライトトラック | Write Fault（`$20`） |

### 制限

- 複数枚のイメージを連結したファイルは、1枚目だけを使う。2枚目以降の選択は（未実装）
- フォーマットされていないトラック（オフセットが0）へのライトトラックはできない。セクタの構成を変えるフォーマットは（未実装）
- 1トラックで扱うセクタは64個まで、1トラックのデータは16KBまで。超えた分のセクタはないものとして扱う
- リードデータ（m）・ライトデータ（m）・リードトラックで一度に扱うのは `$1900` バイトまで
- サイドの比較（コマンドの C フラグ）はしない。H の値は見ない
- 削除マーク付きのライトデータは、通常のライトデータとして書く

### IPL ROM がないときの起動

`IPLROM.X1`・`IPLROM.X1T` がないときは、エミュレータが `FD0` のイメージから起動プログラムを読む。D88形式のときは、256バイトを1レコードとして `トラックNo.*2+サイド = レコード/16`、`R = レコード%16+1` のセクタを読む。1トラック16セクタ・1セクタ256バイトのディスクだけが対象。

## ソースの構成（ディスクイメージの部分）

- `src/X1IO.has`：ＦＤＣ（MB8877）のエミュレーション。2D形式の読み書き。D88用ルーチンの呼び出し
  - `E_RDST`：上位バイトが `$FF` ならリードデータ（1セクタ）、下位バイトがリードの終了時のステータス
- `src/X1D88.has`：D88形式の処理
  - `D88INIT`：初期化（`INITIO` から）
  - `D88OPEN`：ヘッダを読んで形式を判定する（`FOPEN` から）
  - `D88RD`：リードデータ・リードトラック（`RDATA` から）
  - `D88RA`：リードアドレス（`READADRS` から）
  - `D88WC`：ライトデータ・ライトトラックの開始（`WDATA` から）
  - `D88WR`：受け取ったデータの書き込み（`OTESCT` から）
  - `D88CHK`・`D88RREC`：IPL ROM がないときの起動用（`X1EMU.has` の `FC_02` から）
  - `FDINIT`・`FDSET0`：イメージのファイル名の表（`FDNAME`）の初期化（`X1EMU.has` の `START` から）
  - `FDSWAP`：入れ替えの要求（`FDCHG`）の処理（`X1IO.has` の `O0FF8` → `FDCHGX` から）
  - `FDNEXT`：次のファイル名のある組を探す（`FDSWAP` と、`X1STAT.has` の `STVDISP` から）
- `src/X1EMU.has`：`FDCHK` が起動時にファイルを開けるか確かめる。`CNFANA` が `FD10`～`FD93` を読んで `FDNAME` に入れる。キー割り込みの `FDCHGK` が OPT.2+テンキーで `FDCHG`（ドライブごとの要求の回数）を 1 増やす
- `test/`：`X1D88.has` と `X1IO.has` のＦＤＣ部分のテスト。`run68x` の上で動かす
  - `T88.has`・`t88.py`：`X1D88.o` だけをリンクして各ルーチンを直接呼ぶ
  - `T2.has`・`t2.py`：`X1IO.o` の `I0F00`・`O0F00` をＦＤＣのポートとして呼ぶ。変更前の `X1IO.has` と結果を比べる

## 音源

### CONFIGファイルの指定

| 指定 | 値 | 初期値 | 内容 |
|---|---|---|---|
| `PSG` | `ON` / `OFF` | `ON` | ＰＳＧをエミュレートするか |
| `OPM` | `ON` / `OFF` / `MIX` | `OFF` | ＦＭ音源をエミュレートするか |

`ON`・`MIX` 以外の値は `OFF` として扱う。`OPM=OFF` のときは、ＦＭ音源ボードのＣＴＣ（`$0704`～`$0707`）への出力も無視する（従来どおり）。

### OPM のチャンネルの使い方

ＰＳＧは X68000 の OPM の ch5～ch8 で鳴らす（トーンA・B・C が ch5・6・7、ノイズが ch8）。

| `OPM` | ch1～ch4 | ch5～ch8 |
|---|---|---|
| `OFF` | 使わない | ＰＳＧ |
| `ON` | ＦＭ音源 | ＦＭ音源とＰＳＧの両方が書く。ＦＭ音源が音色（`$24`～`$27`）を書くと、次にＰＳＧのミキサーが書かれたときにＰＳＧの音色へ戻す |
| `MIX` | ＦＭ音源 | ＰＳＧ。ＦＭ音源からの ch5～ch8 への書き込みは捨てる |

`OPM=MIX` のとき、X1 のプログラムがＦＭ音源のデータポート（`$0701`）に書いた値は、アドレス（`$0700`）によって次のように扱う。

| OPM のレジスタ | 扱い |
|---|---|
| `$08`（キーオン） | データの bit2 が 1（ch5～ch8）なら捨てる |
| `$0F`（ノイズ） | 捨てる（ノイズは ch8 だけに効く） |
| `$20`～`$FF` | アドレスの bit2 が 1（ch5～ch8）なら捨てる |
| そのほか（`$01`、タイマー、LFO など） | `ON` のときと同じ |

`MIX` でＰＳＧを鳴らすには `PSG=ON`（初期値）のままにする。`MIX` は `PSG` の指定を変えない。

### ソースの構成（音源の部分）

- `src/X1EMU.has`：`CNFPSG`・`CNFOPM` が CONFIG を読む。`F_PSGSW` は `$00`=OFF / `$FF`=ON、`F_OPMSW` は `$00`=OFF / `$FF`=ON / `$01`=MIX
- `src/X1IO.has`：`O0700`（ＦＭ音源）、`OPMMIX`（`MIX` のときの振り分け）、`O1B00`（ＰＳＧ）、`INITFM`（初期化）

## ステータス行

X1 の画面のすぐ上に、8 ライン（16 ラスタ）のステータス行を出す。

### CONFIGファイルの指定

| 指定 | 値 | 初期値 | 内容 |
|---|---|---|---|
| `STATUS` | `ON` / `OFF` | `ON` | ステータス行を表示するか |

`ON` 以外の値は `OFF` として扱う。`OFF` のときは、画面の作り（表示期間、Y スクロール、テキストパレット）がステータス行を足す前と同じになる。

### 表示の内容

80 桁を 4 つに分け、ドライブ 0～3 に 20 桁ずつ使う。

| 桁 | 内容 |
|---|---|
| 0 | LED（6×6 ドット） |
| 1 | ドライブの番号（`0`～`3`） |
| 2 | `:` |
| 3～18 | 今入っているイメージのファイル名（16 桁まで。ディレクトリ名とドライブ名は出さない。長い名前は後ろを切る） |
| 19 | 空き |

- 背景は暗いグレー（`#444`）
- LED は、リード（リードデータ・リードトラック）のコマンドで緑、ライト（ライトデータ・ライトトラック）のコマンドで赤になる。最後のコマンドから垂直同期 8 回（約 0.13 秒）で消える。消えているときは黒
- リードアドレス・シークなどでは点かない。書き込み禁止で断られたライトでも点かない
- ファイル名は、起動時と、イメージを入れ替えたときに描き直す。イメージの指定がないドライブは番号だけが出る
- OPT.2+テンキーを押すと、次の垂直同期で、次に入るイメージのファイル名に描き替える。続けて押せば、そのたびに次の名前に替わる。実際にイメージが替わるのは X1 が次にＦＤＣへコマンドを書いたときなので、表示のほうが先に替わる。ほかにイメージの指定がないドライブは変わらない
- 文字は X1 の CGROM（8×8 ドット）で描く。色は X68000 のコンソールの白（テキストパレット 3）
- 2 バイト文字のファイル名は正しく出ない

### 画面の作り

- 描く先は X68000 のテキスト画面（X1 のグラフィックを出している画面）。X1 の画面は SCREEN 0 が 512 ライン目から、SCREEN 1 が 768 ライン目からにあるので、ステータス行はその直前の 504～511 ライン目と 760～767 ライン目の 2 か所に同じものを描く
- この 8 ラインはテキストプレーン 3 を 0 にして、テキストパレットの 3～7 で出す（X1 のグラフィックは、プレーン 3 を 1 にしてパレットの 8～15 で出している）

| テキストパレット | 使い方 | 値 |
|---|---|---|
| 3 | 文字 | 変えない（コンソールの白） |
| 4 | 背景 | `#444`（G・R・B とも 8/31） |
| 5 | LED 消灯 | 黒（値 0 は透明になるので、R だけ 1/31） |
| 6 | LED リード | 緑 |
| 7 | LED ライト | 赤 |

- テキストパレットの 4～7 は、最初に元の値を覚えておき、終了するときに戻す
- グラフィック画面の同じ 8 ラインは空にしておく
- 描く間だけ CRTC R21（テキスト画面の同時アクセス）を 0 にし、終わったら元の値に戻す。X1 のグラフィックの処理が同時アクセスを有効にしたままにするため
- Y スクロール（CRTC R11・R13）は `$01F8`（SCREEN 0）と `$02F8`（SCREEN 1）。`STATUS=OFF` のときは `$0200` と `$0300`
- 表示期間は縦 416 ラスタ。`STATUS=OFF` のときは 400 ラスタ

| モード | | R06（表示開始） | R07（表示終了） | X1 の画面の位置 |
|---|---|---|---|---|
| 31kHz | `OFF` | 40 | 440 | |
| 31kHz | `ON` | 24 | 440 | `OFF` と同じ |
| 24kHz | `OFF` | 31 | 431 | |
| 24kHz | `ON` | 23 | 439 | `OFF` より 8 ラスタ下 |

- CRTC の表（`DCRT24`・`DCRT31`）は `OFF` の値のままで、`ON` のときは表を書いたあとに `STINIT` が R06・R07 を書き直す

- 24kHz は垂直の総ラスタ数が 448 しかないので、上下に 8 ラスタずつ広げた
- テキスト画面の 504～511 ライン目はデバッガの画面の最後の 8 ラインにあたる。デバッガの画面に入るときにステータス行を消し、X1 の画面に戻るときに描き直す

### ソースの構成（ステータス行の部分）

- `src/X1STAT.has`：ステータス行の処理。リンクの先頭に置く。`.data` と `.bss` は使わず、ワークは `.text` に置く
  - `STSET`：表示する・しないを切り替える（`X1EMU.has` の `CNFSTS` から）。`STSCR0`・`STSCR1` が Y スクロールの値で、`X1IO.has` が読む
  - `STINIT`：表示期間を広げ、ステータス行を描き直す（`X1EMU.has` の `SETCRTC`、`Z80DB.has` の `X1CRT` から）
  - `STHIDE`：SCREEN 0 の上のステータス行を消す（`Z80DB.has` の `DBCRT` から）
  - `STEXIT`：SCREEN 0 の上を消し、テキストパレットを戻す（`X1EMU.has` の `RETCRTC` から）
  - `STNAME`：ファイル名を描く（`X1D88.has` の `FDSWAP` から）
  - `STLEDR`・`STLEDW`：LED を点ける要求を出す（`X1IO.has` の `RDATA`・`WDATA` から）
  - `STVDISP`：垂直同期の割り込み。LED を描き、入れ替えの要求（`FDCHG`）が立っていたら次のファイル名を描き、28 回に 1 回 `FLASH`（文字の点滅）へ行く
- `test/T3.has`・`test/t3.py`：`X1STAT.has` のテスト。VRAM・パレット・CRTC のアドレスをメモリ上のバッファに差し替え、`rte` を通常の復帰に置き換えたコピーをアセンブルして使う
