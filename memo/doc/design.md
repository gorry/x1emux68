# 設計の方針

## D88形式のディスクイメージ

- 形式はファイルの中身で見分ける。拡張子は見ない
  - 理由：`.d88` のほかに `.d77` などの名前でも同じ形式が使われる。2Dのベタイメージは、ヘッダの検査（`spec.md`）でD88と間違えることがまずない
- 従来の2Dのベタイメージの処理はそのまま残し、ドライブごとに形式を持つ
  - 理由：これまで動いていたイメージの動作を変えない。ＦＤＣの各コマンドの入口でD88用のルーチンを呼び、D88でなければ何もせずに元の処理へ進む
- D88の処理は `src/X1D88.has` に分ける。`X1IO.has` には呼び出しだけを置く
  - 理由：`X1IO.has` は `.s` の短い分岐が多く、途中にコードを足すと届かなくなりやすい
- `X1D88.has` は `.data` を使わない。変数は `.bss`、参照は絶対アドレス
  - 理由：`X1IO.has` の変数は `変数-A_MEM(aME)` の16ビット相対で読まれている。`.data` が増えると `A_MEM`（`.bss` の先頭付近）から遠ざかる。`.bss` なら `A_MEM` より後ろに付くので影響しない
  - `.text` は `A_BAS` から `.data` の表（`T_OPC` など）までの16ビット相対の間に入る。今の余裕は `X1DB.x` で約3KB。`.text` を増やすときはリンクマップで確かめる
- リンクの順は `Z802.o` と `X1IO.o` の間
  - 理由：`X1IO.has` の `END` を `.bss` の最後のままにする
- セクタは C（トラックレジスタの値）と R（セクタレジスタの値）の両方で探す
  - 理由：実際のＦＤＣの動作に合わせる。同じトラックに違う C のセクタがあるディスクを区別できる
- トラック単位でファイルから読み、1トラック分をメモリに持つ
  - 理由：セクタの並びを調べるのに毎回ファイルを読まずに済む。同じトラックの続けての読み書きが速い
- 書き込みはセクタのデータをその場で書き換える。ファイルの大きさとトラックの構成は変えない
  - 理由：D88はトラックがファイルの中に詰めて並ぶので、構成を変えると後ろのトラックを全部ずらすことになる。ライトトラック（フォーマット）は、今あるセクタの中身を埋めるだけにした
- リードの終了時のステータスは、転送バイト数からではなく変数 `E_RDST` から決める
  - 理由：D88では1セクタが256バイトとは限らず、削除マークやCRCエラーも返すので、バイト数だけでは決められない

## ディスクイメージの入れ替え

- 今入っているイメージのファイル名は、これまでどおり `X1IO.has` の `FD0`～`FD3` に置く。入れ替え用の名前は別の表（`X1D88.has` の `FDNAME`、`.bss`）に持ち、入れ替えのときに `FD0`～`FD3` へコピーする
  - 理由：ファイルを開く処理（`FOPEN`）と IPL ROM なしの起動（`FC_02`）を変えずに済む。表を `X1IO.has` の `.data` に置くと `A_MEM` から遠ざかる（上の「D88形式のディスクイメージ」と同じ理由）
- キー割り込みでは要求のフラグ（`FDCHG`）を立てるだけにし、ファイルの入れ替えはＦＤＣのコマンドレジスタへの書き込み（`O0FF8`）のときに行う
  - 理由：割り込みの中でファイルを閉じたり名前を書き換えたりすると、ＦＤＣの処理が DOS コールの途中だった場合に壊れる。コマンドの書き込みはディスクを使うたびに必ず通るので、ここで見れば次のアクセスに間に合う
- 使用中（ファイルが開いている）のドライブは、入れ替えのあとすぐ開き直す
  - 理由：リード・ライトのコマンドはファイルが開いている前提で動く。開き直さないと、次にモーターONかシークが来るまで読めない
